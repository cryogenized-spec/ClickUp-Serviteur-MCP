# Webhook ingestion

The optional POST /clickup/webhook route is disabled unless CLICKUP_WEBHOOK_ENABLED=true and CLICKUP_WEBHOOK_REGISTRATIONS is supplied as a protected Worker secret. The secret is a JSON array of operator-provisioned records containing webhookId, workspaceId, subject (github:<numeric-id>) and secret (the signing secret ClickUp returned when the webhook was created). Never commit or expose this configuration. The configured Workspace and staff allowlist must match each record.

The receiver verifies the native X-Signature HMAC on the exact request bytes, then persists task ID, event type, receipt time, deduplication key and optional bounded routing metadata into a private Durable Object partitioned by Workspace and actor. ClickUp's webhook ID plus history item ID forms the replay key; exact body digest is used if no history IDs exist. Storage is bounded to 5000 hints per partition, with seven-day expiry. It acknowledges only after successful persistence. No raw comments, descriptions, attachments or secret values are persisted in the event store.

The Worker has no public event-listing route. The Workspace attention report optionally includes up to ten recently changed tasks, verified through fresh upstream task reads with the caller's OAuth token. It reports incomplete coverage on denied tasks and storage errors. It does not label these changes as actual Inbox items, and explicit List-scoped reports do not receive Workspace hints. Subscription creation, rotation and deletion via MCP remain subsequent work. No live webhook registration or secret configuration has been performed.

References: https://developer.clickup.com/docs/webhooks, https://developer.clickup.com/docs/webhooksignature, https://developer.clickup.com/docs/webhookhealth.

## Review checkpoints

Use clickup_get_pending_activity to retrieve all available unacknowledged changes across storage pages in one call, grouped by freshly verified task. By default there is no application-imposed event, page-count or task-verification limit; max_results is an optional caller-requested result bound. Continue with the paired event cursor while incomplete=true; if resume_from_beginning=true, retry from the beginning instead. No artificial ClickUp request-per-minute or verification-count ceiling is enforced. On an actual upstream 429 during task verification, the read waits 60 seconds and retries the same safe GET without a retry-count ceiling. This can exceed MCP client connection timeouts; if disconnected, no events have been acknowledged, so a later read can resume from the saved cursor or start over. Every distinct task still receives an authoritative task GET; successful parent List authorization is reused only in the current read for up to ten seconds and discarded on retries. Direct task GET 404 responses are counted as unverified and the scan continues without exposing the task or acknowledging its events. Other transient verification failures are retried twice (one and two seconds); if still unsuccessful, preserve the last processed cursor and report the sanitized error code and HTTP status, if available. A resumed scan with no progress retains its supplied cursor rather than restarting from the beginning. Fetch task details and comment history for context, then present a briefing. Only after user approval call clickup_acknowledge_activity with the exact reviewed event keys for each task. Reading is non-consuming, acknowledgement is idempotent within retention, and new events arriving during a briefing remain pending. Neither operation changes ClickUp Inbox state. Expired or inaccessible events cannot be acknowledged through a task-scoped tool; coverage is explicitly incomplete. Storage retains a maximum of 5000 hints for up to seven days, not an indefinite delivery guarantee.

## Routing metadata (2026-11-26)

The signed history item may provide optional metadata: actor_user_id, comment_id, list_id (historical parent hint), field, occurred_at (milliseconds), assignee_user_id (affected user on add/remove), and mentioned_user_ids (only structured individual tag segments, never plain-text guesses). Missing or unsupported metadata is omitted; absence of a mention is not proof no mention exists. Author IDs identify the event actor, not necessarily the original author of an edited comment. IDs are normalized as bounded decimal strings; field names are allowlisted. No raw before/after data, comment text, profile names, email addresses or attachments are persisted. Existing rows remain readable without metadata. A separate SQLite metadata table is created idempotently and orphan rows expire with the existing event records. Metadata is sanitized again at persistence and response boundaries, and is returned only after the existing authoritative task authorization succeeds. The caller's current OAuth scope remains authoritative; historical List hints do not authorize access. Fetch current comments directly from ClickUp for semantic interpretation and subsequent replies.

This first increment intentionally preserves existing replay keys, subscriptions, acknowledgement semantics and cursor ordering. Cross-subscription deduplication, server-side query filters and independent durable consumer checkpoints require separate tests and implementation. New metadata is forward-only unless ClickUp delivers another signed event; do not invent metadata for old records.
