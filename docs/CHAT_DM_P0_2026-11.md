# Chat/DM identity — P0 source implementation (13 November 2026)

Parent issue: [#135](https://github.com/cryogenized-spec/ClickUp-Serviteur-MCP/issues/135). Cross-reference [#120](https://github.com/cryogenized-spec/ClickUp-Serviteur-MCP/issues/120).

**Architecture:** One unified operational ClickUp Serviteur MCP. The internal staging Cloudflare Worker is a deployment/testing environment, never an additional ChatGPT connector. This PR changes only source and synthetic tests; no actual staff DM, Chat write or company deployment.

## What was added

- Normalize known v3 Chat list and channel response envelopes: legacy `channels`/`messages`/`members` and v3 `data` arrays or objects. Unknown or mismatched resource shapes **fail closed**, not an empty success.
- Four new named tools in the same OAuth Workspace-bound catalogue: `clickup_get_chat_channel_details` (not proof of identity), `clickup_get_chat_channel_members` (bounded cursor page), `clickup_verify_chat_recipients` (read-only exact member-set proof), and `clickup_open_direct_message` (create or find existing DM, then same-Workspace channel and members readback).
- Opening a DM uses official `POST /api/v3/workspaces/{workspace_id}/chat/channels/direct_message` with only `user_ids`, no message content. Accept 1–15 unique verified ClickUp Workspace user IDs; self-DM requires the explicit `self_dm:true` option and an empty set.
- For DM sends, `clickup_send_chat_message` now requires the supplied expected participant IDs (or explicit self-DM), independently verified against the complete actual channel member list, including the authenticated sender. Neither a guessed channel ID nor channel creator/display name verifies a recipient. A mere open/preview never sends a Chat message.
- Fail closed when members are missing, ambiguous, duplicated, cursor-incomplete, foreign to Workspace, not in the existing authorised member list, or when DM/GROUP_DM type does not match the actual participant set. No silent fallback to a public channel.

## Explicit limitations and acceptance gates

ClickUp v3 Chat is [experimental](https://developer.clickup.com/docs/chat). Public endpoint docs provide route and request contract, but not enough provider-specific payload examples for all response shapes. Live tests on **disposable internal staging account/self-DM only**, plus a separate user-authorised normal DM, must confirm response-envelope mapping, actual member ID shapes, page cursors, author identity, DM type and existing vs newly created DM. If ClickUp returns a valid member shape not yet recognized, the implementation rejects it rather than assuming recipient identity. Staging evidence determines any narrow normalization changes.

## Official endpoints

- [Create or get a Direct Message](https://developer.clickup.com/reference/createdirectmessagechatchannel): 200 existing or 201 created, user_ids up to 15, empty for self-DM
- [Retrieve a Channel](https://developer.clickup.com/reference/getchatchannel): verified channel ID within authorized Workspace path
- [Retrieve Channel members](https://developer.clickup.com/reference/getchatchannelmembers): bounded cursor pages; exact identity is independent of channel metadata
- [Retrieve Channel messages](https://developer.clickup.com/reference/getchatmessages): cursor pagination, explicit text formats
